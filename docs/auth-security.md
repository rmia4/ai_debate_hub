# 인증·보안

MCP 요청은 MCP 표준 OAuth 2.1 액세스 토큰으로, 웹 화면은 소셜 로그인 세션으로 인증합니다. 주소에 비밀값을 넣는 방식은 쓰지 않습니다.

## 기준

- **클라이언트 지원:** Claude 커스텀 커넥터는 OAuth 방식 원격 서버를 지원하며, 콜백 주소는 `https://claude.ai/api/mcp/auth_callback`입니다 ([Claude 도움말](https://support.claude.com/en/articles/11503834-building-custom-connectors-via-remote-mcp-servers)). Codex는 `codex mcp login`으로 원격 서버의 OAuth 로그인을 수행합니다 ([Codex MCP 문서](https://developers.openai.com/codex/mcp)).
- **명세:** 2026-07-28 MCP 인가 명세를 따릅니다. 보호 리소스 메타데이터 제공, 토큰 대상(리소스) 검증, 쿼리 문자열 토큰 거부는 필수입니다. CIMD는 권고, DCR은 하위 호환용입니다 ([MCP 인가 명세](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)).
- **구현 방식:** 인가 서버를 직접 작성하기보다, 아래 요구 사항(CIMD·DCR, PKCE, `resource`, 연결 단위 폐기)을 제공하는 라이브러리와 버전을 먼저 고릅니다. 그 스키마·폐기 정책에 맞춰 설계를 조정합니다. 라이브러리의 리프레시 토큰 재사용 유예 정책이 "연결 단위 즉시 폐기"와 맞는지 반드시 확인합니다 ([RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)).
- **라이브러리 선정 조건:** CIMD 조회의 SSRF 방어와 아래 연결 교체의 동시성 보장을 확인합니다. 라이브러리가 연결 테이블을 관리하면 부분 유니크 인덱스 또는 같은 보장을 제공하는 확장 지점이 있어야 합니다. 방어를 직접 구현하기 전에 라이브러리 지원과 1단계 시험 결과를 확인합니다.

## MCP 연결 (OAuth 2.1)

| 항목 | 설계 |
| --- | --- |
| 역할 분담 | `/mcp`는 리소스 서버, 같은 앱의 `/oauth/*`가 인가 서버 |
| 탐색 | 토큰 없는 `/mcp` 요청에 401과 `WWW-Authenticate`(보호 리소스 메타데이터 위치 포함). `/.well-known/oauth-protected-resource`(필수), `/.well-known/oauth-authorization-server` 제공. 인가 응답에 `iss` 포함 |
| 클라이언트 등록 | **Client ID Metadata Documents(CIMD)** 를 기본 경로로, DCR을 하위 호환 경로로 지원. 실제 사용 방식은 두 클라이언트의 동작과 라이브러리 지원 범위를 1단계에서 확인해 확정 |
| 인가 요청 보존 | `/oauth/authorize` 요청(클라이언트, 리디렉트 주소, PKCE 챌린지, `resource`, `scope`, `state`)을 서버에 저장. 로그인 후 동의 제출은 이 저장 기록의 ID로만 연결. 브라우저가 보낸 숨은 필드로 클라이언트·리디렉트 주소·참여자를 정하지 않음 |
| 인가 | 인가 코드 + PKCE(S256) 필수, 리디렉트 주소 정확 일치. HTTPS 또는 네이티브 클라이언트의 로컬 루프백 콜백을 허용. `resource`는 이 서비스의 정규 주소(`https://<서비스>/mcp`)만 허용 |
| 참여자 지정 | 동의 화면에서 사용자가 "Claude용/Codex용" 역할을 지정. 서버는 승인된 역할로 요청을 처리하며 **실제 모델·앱의 진위까지 검증하지는 않음**. 클라이언트 이름·CIMD 도메인은 기본값 추천에만 사용 |
| 연결(grant) | 동의 1회 = 연결 1개(`oauth_connections`). 인가 코드·모든 토큰은 연결 ID에 묶임. 사용자·참여자당 미폐기 연결 1개. 같은 역할로 새로 연결하면 동의 화면에 교체될 기존 연결을 표시. 승인 시 사용자 행 잠금 아래 기존 연결 폐기(만료됐지만 미폐기인 연결 포함)와 신규 연결 생성을 한 트랜잭션으로 처리하고, `(user_id, participant) WHERE revoked_at IS NULL` 부분 유니크 인덱스 또는 라이브러리의 동등한 제약으로 보장 |
| 인가 코드 | 10분 유효, 1회용. `used_at`이 비어 있을 때만 갱신하는 조건부 UPDATE로 동시 요청에서도 한 번만 교환 |
| 토큰 수명 | 액세스 토큰 1시간. 리프레시 토큰은 갱신 때마다 새로 발급하되 만료는 **연결 생성 시점 기준 30일 고정**(갱신으로 연장되지 않음). 만료 후 재연결 필요 |
| 토큰 교체·재사용 감지 | 갱신은 트랜잭션으로 처리. 사용된 리프레시 토큰은 삭제하지 않고 `used_at`을 남김. 이미 사용된 토큰이 다시 오면 **그 연결에서 파생된 토큰 전체와 연결을 폐기**. 응답 유실 재시도·동시 갱신은 직전 토큰에 한해 30초 유예를 두고, 연결당 미사용 리프레시 토큰은 1개만 유지 ([2단계 기록](stage2-auth.md#리프레시-토큰-유예-정책-30초)) |
| 폐기 즉시성 | 연결 해제·교체·재사용 감지 시 액세스 토큰도 즉시 거부 (매 요청마다 DB에서 연결 상태 확인). 계정 정지는 연결 폐기 없이 사용자 상태 검사로 차단 |
| 관리 | 연결 설정 화면에서 연결된 앱(역할, 클라이언트, 마지막 사용 시각) 확인과 연결 해제 |

## CIMD 조회와 루프백 콜백

- 서버가 CIMD 문서를 가져올 때는 사설·루프백·링크 로컬 등 비공개 주소를 차단합니다. DNS 해석 결과와 실제 접속 대상, 리디렉션을 따르는 경우 각 목적지를 재검증하며, 응답 크기·시간·리디렉션 횟수를 제한합니다. 라이브러리의 방어 범위를 선정 조건과 1단계 시험에 포함합니다.
- 브라우저가 클라이언트로 돌아가는 OAuth 리디렉트와 서버의 메타데이터 조회는 별도 정책입니다. 서버 조회에서 루프백을 차단하더라도 Codex 같은 네이티브 클라이언트의 등록된 로컬 루프백 콜백은 허용합니다.
- 루프백 콜백만 등록한 클라이언트에는 동의 화면에서 호스트명과 함께 다음 경고를 표시합니다: "이 연결은 현재 기기의 로컬 앱으로 돌아갑니다. 직접 시작한 연결인지 확인한 뒤 허용하세요."

출처: [MCP 인가 보안 지침 — CIMD 보안](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations#client-id-metadata-document-security)

## 웹 보안

- **웹 세션:** DB에 저장한 세션 ID를 서명된 쿠키(HttpOnly·Secure·SameSite=Lax, 만료 7일)로 전달합니다.
- **권한:** 모든 `/app` 경로는 로그인 필수, `/admin`은 `admin` 역할만 허용합니다. 다른 사용자의 토론방 ID 접근은 404로 응답합니다.
- **CSRF:** 웹 세션으로 수행하는 요청(토론 생성·종료·삭제, 탈퇴, 연결 해제, 동의 제출)에만 CSRF 토큰을 적용합니다. `/mcp`, `/oauth/token`, `/oauth/register` 같은 프로토콜 엔드포인트는 각 프로토콜의 인증·검증(액세스 토큰, PKCE, 클라이언트 검증)을 적용합니다.
- **마크다운 렌더링:** `marked`로 변환한 HTML을 `sanitize-html`로 정제해 허용 태그만 남기고, `javascript:` 등 위험한 링크 프로토콜을 차단합니다. AI가 쓴 본문도 외부 입력으로 취급합니다.
- **공통:** 요청 크기 제한, 보안 헤더(CSP 등)를 적용합니다.

## 남용 방지

- 가입·로그인·인가·클라이언트 등록·제출 횟수 제한은 서버리스 인스턴스 간 공유되도록 DB(`rate_limits`)에 기록합니다.
- 제출 제한은 토큰이 아닌 사용자·연결 단위로 계산합니다.
- 횟수 제한 카운터는 제한 키·시간 구간에 유니크 제약을 두고 `INSERT … ON CONFLICT … DO UPDATE SET count = count + 1 RETURNING count` 형태로 원자적으로 증가시킵니다. 반환된 값으로 허용 여부를 판정합니다.
- 토론 생성의 개수·용량 검사와 한도 초과 정책은 [사용량 한도](architecture.md#사용량-한도)를 따릅니다.

## 계정 정지와 해제

- 운영자가 `users.status`를 `suspended`로 바꾸면 MCP 판별 함수, 웹 세션 미들웨어, 인가·토큰 발급 엔드포인트(소셜 로그인 완료, 동의 승인, 인가 코드 교환, 리프레시 포함)에서 상태를 검사해 서비스 접근과 새 세션·토큰 발급을 거부합니다. 웹은 정지 안내와 로그아웃만 허용합니다.
- 정지 자체로 기존 연결·세션·토큰을 폐기하지 않습니다. 정지 해제 후 아직 유효한 연결·세션·토큰은 재연결 없이 다시 사용할 수 있습니다. 정지 중 만료되거나 별도 사유로 폐기된 인증 정보는 복구하지 않습니다.
- 토큰의 서명·해시 검증 결과만으로 통과시키지 않고, 요청마다 사용자 상태와 연결의 폐기·만료 상태를 함께 확인합니다.

## 역할과 신원 구분

참여자 선택은 사용자가 지정하는 역할입니다. 서버는 승인된 역할로 요청을 처리하며, 접속한 앱이 실제 Claude·Codex인지까지 증명하지 않습니다.

## 예비안

1단계 시험에서 claude.ai의 OAuth 연결이 막히면, 원인을 해결할 때까지 임시로 사용자별 주소 토큰 방식을 엽니다. 이 방식은 "요청 → (사용자, 참여자)" 판별 함수 뒤에 숨겨, 나중에 제거하기 쉽게 합니다.
