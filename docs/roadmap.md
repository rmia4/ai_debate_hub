# 로드맵과 위험 요소

## 개발 단계

5단계로 진행하며, 각 단계의 완료 조건을 만족해야 다음 단계로 넘어갑니다. 소요 기간은 바이브코딩 기준 예상치입니다.

### 1. 라이브러리 선정·원격 연결 시험 (예상 1.5일)

- 인증·OAuth 라이브러리 후보의 CIMD·DCR·`resource`·연결 단위 폐기 지원과 버전을 확인해 하나로 확정합니다.
- CIMD 조회의 SSRF 방어(비공개 주소 차단, DNS·리디렉션 목적지 재검증, 크기·시간 제한)와 사용자·참여자당 미폐기 연결 1개 보장 수단을 라이브러리 선정 조건에 포함합니다.
- 더미 `get_state`와 최소 인가 서버를 Vercel에 배포합니다.
- **완료 조건:** Claude 커넥터와 `codex mcp login` 양쪽에서 OAuth 연결과 도구 호출 성공, 각 클라이언트가 실제로 쓰는 등록 방식(CIMD/DCR) 확인, 동의 화면의 역할 선택이 토큰에 반영.
- **추가 확인:** 서버의 CIMD 조회는 루프백을 차단하면서 네이티브 클라이언트의 등록된 루프백 콜백은 허용하는지, 루프백 전용 콜백 경고가 동의 화면에 표시되는지 확인합니다. 라이브러리의 연결 제약 확장 방법도 확정합니다.
- 실패하면 원인과 예비안(주소 토큰) 적용 여부를 이 단계에서 결정합니다.

### 2. 회원·OAuth (예상 2.5일, 1단계 결과로 재산정)

- GitHub·Google 로그인, DB 세션, 인가 서버 정식 구성(메타데이터, 인가 요청 보존, 동의 화면, 연결 단위 토큰 관리), 연결 설정 화면, 약관·개인정보 페이지.
- **완료 조건:**
  - 두 계정의 Claude·Codex가 서로 다른 사용자로 판별
  - 연결 해제·교체 후 기존 액세스 토큰 즉시 거부
  - 리프레시 토큰 재사용 시 연결 전체 폐기
  - 정상적인 동시 갱신·응답 유실 재시도 처리
  - 인가 코드 동시 교환 시 한 번만 성공
  - 30일 만료 후 재연결 요구
  - 동시 재연결 후 같은 사용자·역할의 미폐기 연결이 1개만 남음
  - 만료됐지만 미폐기인 연결이 있어도 재연결 성공
  - 정지 계정의 기존 웹 세션·MCP 호출·새 로그인·인가·토큰 갱신 차단
  - 정지 해제 후 미만료·미폐기 인증 정보는 재사용 가능하며, 만료·폐기된 정보는 복구되지 않음

### 3. MCP 핵심 (예상 1.5일)

- 토론 스키마(`owner_id` 포함), 도구 4개, 행 잠금, 공통 처리 순서, 동시·순차 판정 규칙, 입력 길이 제한.
- 일정이 빠듯하면 동시 방식을 먼저 완성하고 순차 방식을 이어 붙입니다.
- **완료 조건:** MCP Inspector로 다음 시나리오 통과.

| 구분 | 시나리오 |
| --- | --- |
| 격리 | 다른 사용자의 토론 ID 접근 시 "존재하지 않음" |
| 공통 | 응답 유실 후 같은 번호 재제출 시 기존 결과 반환 |
| 공통 | 같은 번호 다른 내용 거부 |
| 공통 | `agree`/사인과 새 `proposal` 동시 제출 거부 |
| 공통 | 마지막 라운드·턴의 합의가 `agreed`로 끝남 |
| 동시 | 서로 다른 안에 교차 동의하면 미합의 |
| 동시 | 동시 제출 시 라운드 마감 |
| 동시 | `get_summary`가 진행 중 라운드를 숨김 |
| 순차 | 먼저 제출한 쪽이 선공 |
| 순차 | 동시 첫 제출 시 한쪽만 선공 |
| 순차 | 차례 아닌 제출 거부 |
| 순차 | 수정안 후 상대 사인 → 제안자 사인으로 종료 |
| 순차 | 재수정안 시 사인 초기화 |

### 4. 웹 1단계 (예상 1.5일)

- 소개, 토론 목록·생성·상세, 강제 종료·종료 토론 삭제·내보내기, 계정(사용량·탈퇴), 운영자 화면, 사용량 한도, 하루 1회 정리 작업.
- **완료 조건:** 두 계정이 서로의 토론방을 볼 수 없음, 한도 초과 시 삭제 경로 안내, 종료 토론 삭제 후 생성 한도 복구, 진행 중·타인 토론 삭제 거부, 정리 작업이 만료 데이터를 삭제.
- **한도 검증:** 웹·MCP 동시 생성 시 진행 중 5개·보관 50개 제한 유지, 원자적 횟수 카운터 동작, UTF-8 바이트 기준 용량 계산, 5MB 도달 시 새 생성 차단과 기존 토론 제출 허용을 확인합니다.

### 5. 실제 토론 시험·공개 (예상 1일)

- 두 방식으로 실제 주제를 1~2개씩 토론하고 지시문 문구를 조정합니다.
- 처음 쓰는 사람의 관점에서 가입부터 연결·토론까지 안내 문구를 점검한 뒤 공개합니다.
- **완료 조건:** 안내만 보고 연결과 토론을 마칠 수 있음.

### 6. 프로젝트와 전역 배경

- 토론 배경(2000자, `get_state`마다 전문 전송)으로는 긴 프로젝트 문서를 쓸 수 없어 프로젝트 단위를 둡니다. 프로젝트에는 전역 배경 항목(text 메모, link URL, file 로컬 절대경로)을 두고, 프로젝트 토론은 그중 일부를 참조합니다. 링크·파일은 참여 AI가 직접 읽고 서버는 내용을 가져오지 않습니다.
- MCP 도구 `list_projects`·`get_project`·`get_background`·`add_background`·`update_background`, `start_discussion`의 `project_id`·`background_ids`, `get_state`·`get_summary`의 `references`. 웹 프로젝트·배경 화면과 내보내기. 소프트 삭제와 정리 작업 단계.
- **완료 조건:** 사용자 간 격리, 웹 생성 → MCP 항목 추가 → 프로젝트 토론 → `references`·`get_background`·지시문 흐름, A석·B석 양쪽 수정과 `revision_mismatch`, 길이·URL·경로·개수·종류 검증, 삭제·소프트 삭제·정리, 동시 요청에서 개수·5MB 한도 유지, 계정·운영자 화면의 같은 용량 값(`test/projects.test.ts`).

### 후순위 (필요 시)

이메일 가입, 자동 새로고침, 쟁점 개수 추이, 최대 라운드 변경, 지시문 재발급, 읽기 전용 공유 링크, `resolved_issues`, Claude Code 사용자를 위한 훅 기반 자동 진행.

## 위험 요소

가장 큰 위험은 두 AI가 근거 없이 빨리 합의해 버리는 것이며, 지시문과 판정 규칙으로 완화합니다.

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| claude.ai OAuth 연결 실패 | Claude 쪽 연결 불가 | 1단계에서 가장 먼저 시험. 실패 시 예비안(주소 토큰)을 판별 함수 뒤에 임시 적용 |
| 다른 사용자 데이터 접근 | 토론 기록 유출 | 모든 조회에 `owner_id` 조건, 사용자 범위 저장소 함수로 접근 일원화, 격리 테스트 고정, 타인 토론은 "존재하지 않음" 응답 |
| 토큰 탈취 | 제3자가 해당 사용자 명의로 토론 조작 | 짧은 액세스 토큰 수명, 리프레시 토큰 교체와 재사용 감지 시 연결 단위 일괄 폐기, 발급 이력 보존, 해시 저장, 연결 해제 기능 |
| 사칭 클라이언트의 인가 요청 | 사용자가 모르는 앱에 권한 부여 | PKCE·리디렉트 주소 정확 일치, 동의 화면에 클라이언트 이름과 리디렉트 도메인 표시 |
| CIMD 조회 악용 | 내부 주소 접근·과도한 외부 요청 | 라이브러리의 SSRF 방어 확인, 비공개 주소 차단·목적지 재검증·조회 제한. OAuth 루프백 콜백은 별도 정책 |
| 동시 재연결·만료 연결 잔존 | 같은 역할의 연결 중복 또는 재연결 실패 | 사용자 행 잠금과 폐기·생성 트랜잭션, 미폐기 연결 부분 유니크 제약, 만료된 기존 연결도 폐기 |
| 정지 계정의 우회 접근 | 웹 작업·새 토큰 발급 지속 | MCP 판별·웹 세션·인가 및 토큰 발급 경로에서 사용자 상태 검사. 정지 자체로 연결을 폐기하지 않음 |
| Claude와 Codex 참여자 혼동 | 한 AI가 양쪽 명의로 제출 | 동의 화면에서 역할 지정(앱 진위 검증은 아님), 사용자·참여자당 연결 1개, 교체될 기존 연결 표시 |
| 무료 DB 용량 소진 | 전체 서비스 쓰기 불가 | 생성 시 UTF-8 용량·개수 검사, 종료 토론 삭제, 180일 보존 정책, 운영자 화면에 용량 표시. 진행 중 토론의 제한된 초과분은 허용 |
| 가입·등록 남용 | 자원 소모 | 소셜 로그인만 허용, 동적 등록·생성·제출 횟수 제한, 계정 정지 |
| 무료 호스팅 약관 위반 | 서비스 중단 | 광고·유료 기능 없이 비상업적으로 운영, 수익화 시 유료 플랜 전환 |
| 서로 다른 안에 교차 동의 (동시) | 실제 합의 없이 "합의 완료" 표시 | 같은 `accepted_proposal_id`일 때만 합의 판정 |
| 동의하면서 새 수정안 제출 | 합의 처리와 별도 수정안이 함께 남음 | 동의·사인 제출에는 새 `proposal` 금지 |
| 선점 효과 (순차) | 먼저 말한 쪽 의견에 끌려감 | 지시문에 독립 검토 명시, 중요한 안건은 동시 방식 사용 |
| 근거 없는 조기 합의 | 토론 품질 저하 | 지시문에 "쉽게 동의하지 말 것", 동시 방식 라운드 1 독립 답변·최소 라운드, 순차 방식 제안자 재확인 사인 |
| 동시 제출 경합 | 라운드 미마감, 순차 방식 선공 중복 | `discussions` 행 `FOR UPDATE` 잠금 + 공통 유니크 제약 |
| 응답 유실 후 재시도 | 재제출이 라운드 불일치·차례 위반으로 거부되거나 중복 저장 | 잠금 직후 기존 기록 조회를 검증보다 먼저 수행 |
| 마지막 턴 합의 | `max_reached`로 덮어씀 | 합의 판정을 최대 횟수 판정보다 먼저 수행 |
| 차례가 아닌 AI에 지시 (순차) | 순서 꼬임 | 서버가 거부하고 "상대 차례" 안내 |
| 조회 우회 (동시) | 현재 라운드의 상대 답변을 미리 열람 | MCP 조회는 완료된 라운드만 공개 |
| AI가 도구 대신 채팅으로만 답변 | 기록 누락 | 도구 설명과 지시문에 submit 필수 명시 |
| 긴 답변·악성 마크업 | 토큰 낭비, 웹 화면 스크립트 실행 | 길이 제한, sanitize-html 정제, CSP |
