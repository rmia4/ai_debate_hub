# 웹 화면

공개 소개·로그인 화면, 로그인한 사용자의 작업 화면(`/app`), 운영자 화면(`/admin`)으로 나눕니다. 같은 Express 앱과 DB를 쓰므로 별도 프론트엔드나 추가 호스팅은 필요 없습니다.

| 화면 | 경로 | 기능 | 시기 |
| --- | --- | --- | --- |
| 소개 | `GET /` | 서비스 설명, 사용 방법, 로그인 버튼 | 1단계 |
| 로그인·가입 | `GET /login`, OAuth 콜백 | GitHub·Google 로그인, 첫 로그인 시 자동 가입과 약관 동의 | 1단계 |
| 약관·개인정보 | `GET /terms`, `GET /privacy` | 이용약관, 개인정보 처리방침 | 1단계 |
| MCP 동의 | `GET/POST /oauth/authorize` | 연결을 요청한 클라이언트 이름과 리디렉트 호스트 표시, 루프백 전용 콜백 경고, 같은 앱의 기존 연결 교체 안내, 허용·거부 | 1단계 |
| 연결 설정 | `GET/POST /app/connections` | 서비스 주소, "Claude에 연결"(claude.ai 커넥터 추가 대화상자를 채운 채로 열기)·"Codex에 연결"(3단계 안내 대화상자), 연결된 앱 목록(참여자, 마지막 사용 시각), 연결 해제 | 1단계 |
| 토론 목록 | `GET /app` | 왼쪽: "새 토론방" 버튼, 접히는 "프로젝트" 탭(각 프로젝트·"새 프로젝트"), "전체"(기본)·"진행 중"·"종료" 탭(`?project=<id>`, `?view=active\|ended`), 사용량(진행 중·저장·용량). 오른쪽: 토론 표(주제, 프로젝트·진행 방식, 상태와 진행 중 토론의 차례, 현재/최대 라운드·턴, 최근 수정 시각) | 1단계 |
| 토론방 생성 | `GET/POST /app/new` | 주제, 배경 설명, 진행 방식, 최대·최소 라운드(순차는 최대 턴) 입력 → 토론 ID와 참여자별 지시문을 복사 버튼과 함께 표시. `?project=<id>`이면 참조할 배경 항목 체크박스(기본은 모두 해제, 필요한 항목만 고름) | 1단계 |
| 토론 상세 | `GET /app/d/:id` | 동시: 라운드별 2열 비교와 합의 배지 / 순차: 대화형 타임라인, 사인·다음 차례 표시. 쟁점 목록과 결론. 프로젝트 토론이면 프로젝트 링크, 참조 배경 목록, "토론 중 수정됨"·"삭제됨" 배지(삭제된 text 본문은 펼쳐 볼 수 있음) | 1단계 |
| 프로젝트 생성 | `GET/POST /app/projects/new` | 이름, 설명 (사용자당 10개) | 프로젝트 |
| 프로젝트 상세 | `GET /app/p/:id`, `POST /app/p/:id/edit`, `POST /app/p/:id/delete` | 설명, 배경 항목 표(제목, 종류, 요약 또는 위치, revision, 최근 수정, 수정한 쪽), 프로젝트 안 토론 목록, "배경 추가"·"이 프로젝트에서 새 토론" 버튼, 수정, 삭제(확인란. 진행 중인 토론이 있으면 거부, 종료된 토론은 함께 삭제) | 프로젝트 |
| 배경 추가 | `GET/POST /app/p/:id/backgrounds/new` | 종류(text/link/file), 제목, 요약, 본문 또는 위치 (프로젝트당 30개) | 프로젝트 |
| 배경 보기·수정·삭제 | `GET/POST /app/b/:bid`, `POST /app/b/:bid/delete` | 본문 또는 위치 표시, 수정(hidden `revision`으로 충돌 방지), 삭제(확인란) | 프로젝트 |
| 강제 종료·내보내기 | `POST /app/d/:id/close`, `GET /app/d/:id.md` | 진행 중인 토론 종료, 전체 기록 마크다운 다운로드 | 1단계 |
| 종료 토론 삭제 | `POST /app/d/:id/delete` | 본인 소유의 종료된 토론과 관련 답변 삭제. 실행 전 확인 및 내보내기 안내. 보관 한도 해소 | 1단계 |
| 계정 | `GET/POST /app/account` | 표시 이름, 사용량 현황, 전체 기록 내보내기, 회원 탈퇴 | 1단계 |
| 운영자 | `GET /admin` | 사용자 목록, 사용량, DB 용량, 정리 작업 결과, 계정 정지·해제 (`admin` 역할만) | 1단계 |
| 부가 기능 | — | 이메일 가입, 자동 새로고침, 쟁점 개수 추이, 최대 라운드 변경, 지시문 재발급, 읽기 전용 공유 링크 | 후순위 |

## 표시 규칙

- 토론방은 웹에서 만드는 것이 기본입니다. `start_discussion` 도구는 채팅에서 바로 만들고 싶을 때 쓰는 보조 경로입니다.
- 웹은 사용자에게 진행 중인 라운드의 제출도 보여 줍니다. AI용 MCP 조회 경로에는 "완료된 라운드만 공개" 규칙을 적용합니다([토론 진행과 MCP 도구](discussion-flow.md#공개-규칙)).
- AI 본문은 `marked` → `sanitize-html`로 정제해 렌더링합니다([인증·보안](auth-security.md#웹-보안)).
- 화면은 서버 렌더링 HTML과 소량의 JavaScript(복사 버튼)로 만들고, 모바일 폭에서는 1열로 접습니다.
- 토론방 생성 화면에 "기밀이나 개인정보를 넣지 말라"는 안내를 표시합니다. 배경 추가 화면도 같습니다.
- 배경 화면에는 "file 항목은 참여 AI가 그 파일이 있는 컴퓨터에서 실행 중이어야 읽을 수 있고, 서버는 링크·파일 내용을 가져오지 않는다"를 적습니다.
- 배경 저장 경로(`/app/p/:id/backgrounds/new`, `/app/b/:bid`)만 폼 본문 한도를 600kb로 둡니다(한글 5만 자의 URL 인코딩 약 450KB). 나머지 폼은 20kb입니다.
- 종료된 토론만 참조하는 항목을 삭제하면 목록에서만 사라지고(소프트 삭제), 그 토론의 상세·내보내기에는 "삭제됨"으로 제목·위치·본문이 남습니다.
- 계정 화면의 용량에는 배경 항목이 포함되고, 그중 삭제됐지만 과거 토론 기록 때문에 보관 중인 용량을 따로 보여 줍니다. 전체 내보내기에는 프로젝트와 배경(본문·위치)도 들어갑니다.
- 보관 한도에 도달하면 종료 토론 삭제 경로를 안내합니다. 상세 화면의 삭제는 `agreed`·`max_reached`·`closed`에서만 허용하며, 소유자 검증과 CSRF 검증 후 처리합니다. 진행 중 토론은 먼저 종료해야 합니다.
- 루프백 콜백만 등록된 클라이언트의 동의 화면에는 "이 연결은 현재 기기의 로컬 앱으로 돌아갑니다. 직접 시작한 연결인지 확인한 뒤 허용하세요."를 표시합니다.
- 정지된 계정은 작업 화면에 접근하지 못하며 정지 안내와 로그아웃만 제공합니다. 정지 해제 시 아직 유효한 인증 정보는 다시 사용할 수 있습니다([계정 정지와 해제](auth-security.md#계정-정지와-해제)).
